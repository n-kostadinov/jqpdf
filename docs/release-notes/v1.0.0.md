# jqpdf 1.0.0

First public release of **jqpdf** — a Java library wrapping the
[qpdf](https://github.com/qpdf/qpdf) PDF toolkit through JNI. It ships the
native qpdf libraries for the supported platforms inside a single
self-contained jar: no system qpdf installation, no runtime dependencies,
Java 11+ at runtime.

Bundles qpdf 12.4.2.

## Highlights

- **Fluent job API with full CLI coverage** — all 140 documented options of
  the qpdf CLI across general invocation, advanced control, transformation,
  modification, encryption, overlay/underlay, attachments, inspection,
  JSON, and global limits:
  `Jqpdf.createJob().input("in.pdf").linearize().output("out.pdf").run().orThrow()`
- **Self-contained natives** — bundled qpdf binaries plus a JNI shim per
  platform, extracted and loaded automatically once per JVM
- **Job results, not surprises** — `run()` returns the qpdf exit code and
  all captured output streams; `orThrow()` turns errors into exceptions
  when wanted
- **In-memory I/O** — `input(byte[])`, `input(InputStream)`, and
  `outputMemory()` spill transparently to temporary files and clean up
  afterwards
- **qpdf JSON support** — generate, filter, and feed back the qpdf JSON
  representation, including QPDFJob JSON passthrough via `runFromJson`
- **Testable without natives** — the `QpdfNative` adapter seam accepts a
  fake so job logic stays unit-testable and fast

## Platforms

| Platform | Status |
|---|---|
| Linux x86-64 | built, test suite executed on CI |
| Windows x64 | shim cross-compiled with mingw, test suite executed on CI |
| macOS ARM64 | built, test suite executed on CI — encryption unsupported (below) |
| macOS x86-64 | shim cross-compiled and statically validated (no Intel runners) |

## Known limitations

- **macOS: encryption unavailable.** The official qpdf macOS binaries
  cannot load the OpenSSL legacy provider, so encrypting/decrypting PDFs
  fails with `qpdf: unable to load openssl legacy provider`; every other
  feature works. This resolves when qpdf's release builds change.
- macOS x86-64 shims are statically validated (link + `lipo`) but not
  execution-tested — Intel macOS CI runners no longer exist.
